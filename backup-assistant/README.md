# 备份助手

> 全站备份：数据库（pg_dump）+ 媒体库 + 前端/后端源代码与构建产物；定点定时 + 保留策略 + 完成通知 webhook（云端通道）。免费。

## 功能特性

- **全量备份**：单次备份产出完整 ZIP，内含——
  - `db.dump`：PostgreSQL 逻辑导出（`pg_dump -Fc` 压缩格式，`pg_restore` 可恢复）；
  - `media/`：站点媒体库（`data/media` 上传文件）；
  - `frontend-src/` + `frontend-dist/`：前端源代码（排除 node_modules）与 `.next` 构建产物（排除 cache）；
  - `backend-src/` + `backend-dist/`：后端 Go 源代码（cmd/internal/pkg/db/scripts 等）与 `server.exe` 二进制；
  - `manifest.json`：本次备份各部分的状态与大小清单；
- **定点定时**：每天或每周指定 HH:MM 执行（如每天 03:00）；服务停机错过的时刻，启动后自动补跑一次；
- **内容开关**：数据库 / 媒体库 / 前端 / 后端四类目标可独立开关（默认全开）；
- **保留策略**：超出保留份数自动清理最旧备份（默认 5 份）；
- **部分容错**：单一目标失败（如 pg_dump 缺失）不阻断其余目标，失败原因记入备份记录；
- **下载与通知**：后台历史列表可直接下载备份；完成后 POST 元信息到自定义 webhook（可对接网盘、群机器人）。

## 安装

1. 后台「插件商城」找到「备份助手」；
2. 点击「免费安装」自动激活（无需支付）。

## 配置说明

| 设置项 | 说明 |
|--------|------|
| 定时备份 | off 关闭 / daily 每天 / weekly 每周 |
| 备份时刻 | HH:MM（24 小时制，默认 03:00）；错过的时刻启动后自动补跑 |
| 每周备份日 | 仅每周调度生效（0=周日 … 6=周六，默认周日） |
| 备份数据库 | pg_dump -Fc 导出；需本机有 pg_dump |
| 备份媒体库 | data/media 上传文件 |
| 备份前端 | 前端源代码 + .next 构建产物 |
| 备份后端 | Go 源代码 + server.exe 二进制 |
| pg_dump 路径 | 留空=自动探测 PATH 与常见安装目录（Windows 探测 Program Files\PostgreSQL） |
| 备份专用数据库账号 | 留空=用宿主连接账号；建议为备份单独建只读账号（如 admin） |
| 备份专用数据库密码 | 配合上方账号使用 |
| 保留份数 | 超出自动清理最旧（默认 5） |
| 通知 webhook | 备份完成后 POST 元信息，留空不通知 |

## 数据库备份说明

- 连接信息自动取宿主环境变量（`POSTGRES_HOST/PORT/USER/PASSWORD/DB`），缺失时兜底解析工作目录 `.env`；
- 密码经 `PGPASSWORD` 环境变量传给 pg_dump，不落命令行；
- 恢复方式：解压备份后执行 `pg_restore -h 主机 -U 用户 -d 库名 db.dump`；
- pg_dump 客户端版本需不低于 PostgreSQL 服务器版本；
- 本机无 pg_dump 时数据库部分记为失败并显示原因，不影响其余部分备份。

## 后台页面

侧栏「插件 → 备份助手」进入仪表页：定点调度状态、内容开关徽标、立即备份按钮、备份历史（各部分状态徽标 + 下载按钮）。

## FAQ

**Q：备份文件存在哪里？**
A：`data/plugins/backup-assistant/backups/backup-<时间戳>.zip`，在后台历史列表可直接下载。

**Q：备份体积较大怎么办？**
A：备份含 `.next` 构建产物与 `server.exe`，体积可达数百 MB。如只需备份数据，可关闭「备份前端/后端」开关；也可调低保留份数。

**Q：云端通道怎么用？**
A：配置 webhook 后，每次备份完成会把元信息（含各部分状态）推送到该地址，由接收端（网盘机器人、运维脚本等）决定转存方式。

**Q：旧版本（≤1.2.x）的媒体备份还认吗？**
A：认。历史列表自动兼容旧记录（旧备份无各部分状态徽标，下载不受影响）。
